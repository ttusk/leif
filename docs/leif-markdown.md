# Leif Markdown — Schema-2 reference

Leif 3.0 stores every piece of study content as readable Markdown inside the vault folder `Leif/`. This document is the authoritative reference for that layout and syntax. You can edit these files by hand, in any text editor, or with an AI agent — Leif reads them back on the next sync.

> See `docs/manual-editing.md` for the workflows (create, copy, rename, reparent, reorder, duplicate, delete) and `docs/migration-and-recovery.md` for how Markdown became the only study-data authority.

## Invariants

- Every entity document has the frontmatter keys `leif-type`, `leif-schema: 2`, and a unique `leif-id`.
- `leif-id` is a 128-bit, URL-safe base32 string generated by Leif. It never appears in filenames, wikilinks, parent properties, or block markers.
- Each entity document has exactly one H1. The H1 text is the canonical name and is never duplicated in frontmatter.
- Folder placement owns containment. Ordered wikilink lists own sequence.
- Managed regions are fenced with `<!-- leif:<region>:start -->` and `<!-- leif:<region>:end -->`.
- Unknown frontmatter keys, prose, headings, attachments, and content outside managed regions are preserved losslessly.
- Slugs are readable paths. On a name collision Leif appends a numeric suffix such as `-2`, never an ID.
- Reject on merge-conflict markers, future schemas (`leif-schema > 2`), duplicate IDs, duplicate managed regions, and references that resolve ambiguously.

## Vault layout

```text
Leif/
├── diagnosticos.md
└── concursos/
    └── <concurso-slug>/
        ├── concurso.md
        ├── mural.md
        ├── materias/
        │   └── <materia-slug>/
        │       ├── materia.md
        │       ├── assuntos/
        │       │   └── <assunto-slug>/
        │       │       └── assunto.md
        │       └── recursos/
        │           └── <recurso-slug>/
        │               └── recurso.md
        └── registros/
            └── YYYY-MM.md
```

`Leif/diagnosticos.md` is regenerated after validation and is excluded from contest indexing.

## Document reference

Each document below begins with the same reserved frontmatter shape:

```yaml
---
leif-type: <entity>
leif-schema: 2
leif-id: <id>
---
```

### concurso.md

```yaml
data-prova: 2026-09-14
banca: FCC
horas-semanais: 20
meta-questoes-semanal: 500
materia-atual: "[[materias/direito-constitucional/materia]]"
recurso-atual: "[[materias/direito-constitucional/recursos/aula-03/recurso]]"
```

Managed region:

```md
## Ordem do ciclo

<!-- leif:materias:start -->
1. [[materias/portugues/materia|Português]]
2. [[materias/direito-constitucional/materia|Direito Constitucional]]
<!-- leif:materias:end -->
```

`materia-atual` and `recurso-atual` are the recommendation pointers, stored as readable wikilinks. Saving, editing, or deleting a Registro never changes them; only an explicit learner action advances or restores the recommendation.

### materia.md

```yaml
ativa: true
minutos-planejados: 60
etapa: Teoria
```

Managed regions:

- `assuntos`: ordered wikilinks to child assunto documents.
- `recursos`: ordered wikilinks to child recurso documents.

Valid unlisted child folders are appended to the appropriate region on the next sync.

### assunto.md

The H1 is the assunto name. Initially it requires no domain property beyond the common metadata. Free-form notes are allowed below.

### recurso.md

```yaml
formato: pdf
meta: 320
unidade: paginas
concluido: false
```

`meta` and `unidade` are both present or both absent. Accepted units are `paginas`, `questoes`, `aulas`, and `minutos`. `formato` is extensible; unknown future values are preserved and not destructive. Initial known formats: `pdf`, `video`, `questoes`, `livro`, `link`, `outro`.

Migration-only keys:

- `progresso-importado` and `acertos-importados` carry an `ImportedProgress` baseline from legacy notebook counters so existing registros are not double-counted.

Managed regions:

- `assuntos`: unordered readable wikilinks to zero or more assuntos in the owning Matéria.
- `acessos`: ordinary Markdown links with optional labels, each pointing to a URL or vault file through which the Recurso can be reached.

A Recurso completes when accumulated registros reach its goal, or when `concluido: true` is set explicitly. A goal-less Recurso is completed only by `concluido: true`.

### registros/YYYY-MM.md

```yaml
leif-type: registros
leif-schema: 2
leif-id: registros-<contest-id>-2026-07
mes: 2026-07
```

One monthly document physically stores all Registros of its Concurso and month. The document is not a domain aggregate: every Registro remains independently identified and independently editable.

The managed `registros` region contains one H2 section per Registro:

```md
## 2026-07-27 · Português

leif-id:: 01J...
data:: 2026-07-27
materia:: [[../materias/portugues/materia]]
recurso:: [[../materias/portugues/recursos/aula-03/recurso]]
assunto:: [[../materias/portugues/assuntos/concordancia/assunto]]
quantidade:: 30
unidade:: paginas
acertos:: 0
concluido:: true
notas:: "Revisão final"
```

- `leif-id`, `data`, and `materia` are required. The Matéria must belong to the document's Concurso.
- `recurso` and `assunto` are optional and must belong to the selected Matéria.
- `quantidade`, `unidade`, and `acertos` are optional but validated as a coherent group (`quantidade⇔unidade`, and `acertos ≤ quantidade`).
- `notas` is an optional JSON-quoted string so line breaks remain on one parseable property line.
- The former `atividade` property and the former `sessoes/` tree are migration-only. Leif backs up and consolidates them automatically.

### mural.md

One per concurso. The H1 is `Mural`, and the body is free-form Markdown. Leif renders it with `MarkdownRenderer` in read mode and offers an explicit edit mode that only patches the body, preserving arbitrary user Markdown.

## IDs and duplicate repair

Leif assigns a `leif-id` to any valid new entity file that lacks one on the next sync. Monthly Registro IDs are inline properties and must be unique across the workspace. Leif repairs a duplicated entity-document ID automatically only when the last-known index proves which document is the new copy; ambiguous document or Registro duplicates block synchronization.

## Validation and diagnostics

Running **Leif: Validar Markdown** rewrites `Leif/diagnosticos.md` with:

- validation timestamp;
- overall result;
- stable diagnostic code;
- severity;
- affected path;
- Portuguese explanation;
- concrete repair guidance;
- informational entries for safe automatic repairs.

A clean run rewrites the file with a successful result. The report is excluded from contest indexing and never becomes study content.
